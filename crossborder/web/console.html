Funnel strip is live — it refreshes after every action and every 8s. Catalogue = SKUs crawled · Allowed = listable · Waiting to buy = orders placed but not yet built into a buy sheet.
How to run the demo — read me

Do the steps top to bottom

  1. Catalogue pipeline — Run listability rules, then Score stockout risk. Watch the strip split into Blocked / In review / Allowed.
  2. Compliance queue — Load pending clusters, then Clear or Kill one row and watch the Allowed/Blocked counts move.
  3. Storefront — Open storefront, add an item, complete checkout. It just works; the order then appears in step 4.
  4. Fulfilment — Build buy sheet from waiting orders → View buy sheet → Reconcile → Pack-out. Or just Fulfil everything in one click.
  5. Signals — Top stockout risk, Detect restocks, Sweep price drift.

Words you'll see

  1. Verdict — Allowed (listable) / Review (needs a human) / Blocked (never listed).
  2. Cluster — a group of SKUs sharing one shelf + one rule; one Clear/Kill moves the whole group.
  3. Waiting to buy — orders that have been placed but not yet built into a buy sheet. Build clears them into a batch.
  4. Batch — one day's orders sealed for buying, split into carts per dark store.
  5. Short — an order that couldn't be fully bought; reconcile fills smallest orders first.
  6. Risk bucket — CRITICAL / HIGH / NORMAL likelihood a SKU goes out of stock.

Note for your manager

Catalogue pipeline

What happens: the buttons rebuild verdicts from your rules. The result box shows the Allowed / Review / Blocked counts, and the top strip updates.

Ingest catalogueLoads inventory_delhi.csv into the products table and parses every pack size to a weight. Already done — only needed after a fresh crawl.
Run listability rulesThe core engine. Runs 39 keyword + 71 shelf + 9 aisle + pack rules; worst verdict wins. Turns 31k SKUs into ~6k Allowed / ~22k Review / ~3.5k Blocked.
Score stockout riskWeighs out-of-stock history, flip rate and discount depth into a CRITICAL/HIGH/NORMAL score used to order the buy sheet and filter basket add-ons.
Classify tailSends the ~9k SKUs no rule matched to the LLM in batches. Does nothing without an API key — safe to skip for the demo.

What happens: a table appears. On each row, Clear makes every SKU in that cluster listable; Kill bans them. The decision sticks even if you re-run the rules.

Fulfilment funnel

Orders → one daily batch → operator buys in Delhi → reconcile → per-customer parcels.

Orders live here first. The number of orders waiting to be bought: —. Adding to the cart on the storefront is not an order — you must complete checkout. Then click Build buy sheet.

Shortcuts for a fast demo:

What happens: waiting orders consolidate into one shopping list per Delhi dark store (three customers buying the same pens become one line of ×3). You buy them, then Reconcile hands the units back to customers — completing whole orders first — and Pack-out makes one parcel each.

Build buy sheetSeals every waiting order into a fresh batch (auto-named, so it always works — no date, no "already exists"). Merges duplicate SKUs, ranks by risk × revenue, splits by dark store.
View buy sheetOne consolidated card per dark store: every item with quantity, a running ₹ total, a Copy shopping list button, and one-tap links. This is what the Delhi buyer works from.
ReconcileAssigns what was actually bought to orders, completing the closest-to-whole first (ties: oldest). Full fill = ships; otherwise short → refund. This is the "who gets the last one" decision.
Pack-out parcelsOne bin per customer with address and parcel weight, marked complete or short.
Seed / Fulfil / Simulate demoShortcuts so you can show the funnel without placing real orders. Fulfil-in-one-click runs build → buy → reconcile at once.

Live signals

The background engines that keep the catalogue honest between crawls.

What happens: each button runs one engine and shows results inline. These normally run on a schedule; the buttons let you demo them on demand.

Top stockout riskShows the CRITICAL-bucket SKUs from the risk engine — the ones a buyer should grab first.
Detect restocksFlags out-of-stock → in-stock transitions; stable ones become relist candidates, flappy ones are held.
Sweep price driftCompares current vs quoted prices; a drop reprices quietly, a rise flags reprice, a viability-breaking rise flags delist.
